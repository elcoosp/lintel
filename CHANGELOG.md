## [Unreleased]

### M1 — independent security validation (release-readiness milestone)

The product's entire pitch is escape-by-default, and that claim rested on
~31 vectors authored by the same agent that wrote the escaper, plus a
differential oracle that is also self-authored. Oracle and implementation
shared a blind spot by construction. M1 closes it:

- **The §7.2 threat corpus expanded from 31 to 893 REAL published payloads**
  — every payload from the OWASP XSS Filter Evasion Cheat Sheet (CC
  BY-SA 4.0) and the PortSwigger Web Security Academy XSS cheat sheet,
  attributed per-vector. Each rides a dynamic child (the `c()` lane) and,
  when URL/scheme-shaped, a dynamic URL attribute (the `u()` lane); each is
  compiled with the real `lintl` binary, the compiled PHP executed under
  real PHP, and the rendered output asserted inert (no payload-injected
  `<script>`/`<img>`/`<svg>`/`<iframe>`/`<style>`/`<object>`/`<embed>` tag,
  no payload-injected `on\w+=` event handler, no live `javascript:`/
  `vbscript:`/`data:text/html` scheme at the start of a rendered URL
  attribute). A compile-time validator rejection (LNL0301 etc.) is the
  strongest inertness and is counted as a passing vector with its code
  pinned. Run `bash scripts/php-gates.sh test` (the `ExpandedThreatCorpusTest`
  lane, data from `php/runtime/tests/ExpandedThreatCorpus.php`, generated by
  `scripts/gen-expanded-threat-corpus.py`).
- **An independent second oracle** (`IndependentOracleTest`): the same
  dynamic values rendered through Blade's `{{ }}` (Laravel's
  `htmlspecialchars`) and Twig's autoescape, compared byte-for-byte against
  Lintl's `c()`/`a()` over 20 values across the child + attribute contexts.
  A disagreement with a third-party engine is a finding, not a rounding
  error. The oracle's first finding: Lintl escapes `'` as `&apos;`
  (`ENT_QUOTES | ENT_SUBSTITUTE | ENT_HTML5`, the modern HTML5-correct
  entity); Blade and Twig escape `'` as `&#039;` (`ENT_QUOTES` without
  `ENT_HTML5`, the older numeric entity). Both are valid HTML5 escaping of
  the apostrophe and render identically in every browser — an investigated,
  inert encoding-style choice, not an escape hole. The oracle normalizes
  the two equivalent apostrophe entities before the byte-for-byte comparison
  so a REAL divergence (which would be a bug) is never masked.
- **No escape hole was found.** All 893 expanded-corpus vectors are inert
  (or rejected at compile time with a pinned LNL code); the independent
  oracle's single divergence is the investigated, inert apostrophe-entity
  choice documented above.

Nothing else lands here first; the 0.1.0 scope is cut below.

## [0.1.0]

This is the first public release of Lintl. It is **early but tested**:
zero external users, zero production soak, and the `lintl` crate name on
crates.io is taken by an unrelated package (the maintainer is running a
community naming process — `scripts/rename-readiness.sh <candidate>`
reports the rename surface for any candidate). The version is 0.1.0, not
1.0.0: the SemVer floor for "the API may still move" (architecture §15
T-18's acceptance is "tagged v0.1.0"). What IS shipped here is reconciled
in §21 with every claim backed by a test, a benchmark or a CI lane —
the language spec the compiler implements is the §4 set with its
executable goldens; the comprehensive feature set covers the compiler,
runtime, streaming and the server adapters, the Laravel/Symfony bridges,
the LSP with its tree-sitter lane, the watch daemon, the incremental
build cache, the playground, the benchmark harness and the deployment
guides. The `v*` tag triggers the T-18 release workflow: five binaries,
SHA256SUMS, build-provenance attestation and a draft GitHub release for
the maintainer's review, with the crates.io publishes and the Packagist
updates in the same workflow; the maintainer reviews the draft and
publishes. Maturity evidence at this tag: the workspace carries 625 unit
+ integration tests across the Rust crates (516) and the six PHP packages
(109; run `cargo test --workspace --all-features` and `bash scripts/php-gates.sh`),
pedantic Clippy is zero-warning, PHPStan is level-max clean, cargo-deny
is clean, and CI runs actionlint, the docs-site link check and the
claims sweep on every push.

### Added

- **The hardened T-12 watch daemon** (`docs/daemon-protocol.md`): the
  socket speaks a length-prefixed JSON protocol both directions (ten
  ASCII digits, newline, payload — `{"path":…}` → `{"ok":true,"php":…}` |
  `{"ok":false,"diag":[…]}`, plus `{"quit":true}`), with bounded client
  reconnect (three attempts, short backoff) and the PHP loader's socket
  lane updated to the same framing with its `proc_open` fallback intact.
  The daemon's recompiles now run through the same content-addressed
  `.lintl-cache/` engine `lintl build` uses — a watch-triggered rebuild
  of unchanged content never recompiles and a reverted edit serves
  instantly, with the counters landing in `.lintl-cache/stats.json` —
  and the shared mutable cache files (`stats.json`, the LSP index's
  `lsp-index.json`) are written under an exclusive `flock(2)` (fs2) so a
  watch daemon, a concurrent build and parallel LSP sessions cannot
  interleave a partial write. Watcher events under `.lintl-cache/` never
  invalidate entries.
- **The monorepo `lsp.include` config** (the Phase 9 §f backlog):
  `lintl.json` gains `{"lsp": {"include": ["packages/*/src/**/*.lintl.php"]}}`
  — when present, the LSP index walks only the configured glob patterns
  (`**` spans directories, `*`/`?` match within one segment, paths are
  root-relative); the dot-directory and `vendor`/`node_modules` skips
  stay (they are properties of the walk — an explicit pattern cannot
  re-include vendored dependencies), and without the key the default
  walk is unchanged.
- **The production deployment guides** (`docs/deployment/`): FPM + nginx
  (OPcache settings and preload), RoadRunner (`.rr.yaml`, worker loop,
  streaming mode), Swoole/OpenSwoole (coroutine server + transport) and
  FrankenPHP (Caddyfile worker mode) — each with prerequisites, install
  steps, the config file, a minimal `.lintl.php` page, a curl
  verification with the expected output and tuning notes. The CI
  `deployment` job runs the RoadRunner guide END-TO-END
  (`scripts/deployment-smoke.sh`): compile with the stream target, serve
  through a real `rr serve` worker pool, curl the endpoint, assert the
  rendered HTML.
- **The anonymous closure return-type rewrite** (the Phase 9 §f backlog):
  the stream target's `: Html` → `\Generator` rewrite (§1a of
  `docs/stream-alignment.md`) now covers braced anonymous closures
  (`static function (): Html { return <b/>; }`) in addition to named
  declarations; body-less arrow functions (`fn(): Html => …`) copy
  verbatim, like the named body-less declarations. A `PHP_BIN`-gated
  execution test invokes the compiled closure and renders without a
  `TypeError`.
- **The persistent LSP workspace index** (§17.1 Q3): `initialize` walks
  the workspace root (`workspaceFolders`/`rootUri`), indexes every
  `.lintl.php` file's component declarations in memory backed by a
  best-effort on-disk cache (`.lintl-cache/lsp-index.json`, keyed by
  file mtime+size), and `textDocument/rename`, `textDocument/references`,
  `workspace/symbol` and `textDocument/definition` consult the index in
  addition to the open documents — a component declared in a closed file
  is renamable (its edits ride the `WorkspaceEdit` against the disk
  bytes), referenceable, symbol-listed and definition-resolvable.
  Client syncs (`didOpen`/`didChange` full sync/`didSave`) re-parse the
  synced text immediately; stale entries evict by mtime+size on access.
- **The content-addressed build cache** (§9.3's warm-build target,
  §17.1-Q2's incremental cache): `lintl build` hashes each source's
  CONTENT with the compile target (SHA-256 — mtime lies after a git
  checkout) into `.lintl-cache/<hash>.php` + a metadata sidecar under
  the workspace root; an unchanged source on the same target reuses the
  cached artifact (warnings replay verbatim in both formats), an edited
  file or a different `--target` misses, and `--no-cache` bypasses
  lookup and store while `check`/`analyze` never read the cache. A
  `.lintl-cache/stats.json` sidecar records the last build's counters,
  and a cold/warm/bypass criterion bench (`cargo bench -p lintl-cli
  --bench build_cache`) pins the 24-file fixture's throughput.
- **`ComponentTester::renderStreaming()`** (`Lintl\Test\ComponentTester`):
  the §10 stream lane of `render()` — the same compile path under
  `--target=stream`, the invocation's generator consumed through
  `\Lintl\stream()`. A PHPUnit parity suite proves the fully consumed
  stream output equals the string target's byte for byte (hostile
  payload included), and the one-target-per-process constraint (the
  stream artifact declares the same function name) refuses loudly.

- **§17.1-Q3 testing helpers** (`php/lintl/src/Test/ComponentTester.php`,
  `Lintl\Test\ComponentTester`): compile-and-render a component source
  in one call without booting a framework — the source compiles on the fly
  through the real binary (the §6.10 compile path), the component invokes
  with named arguments, and the result renders through the §6.8 runtime's
  `\Lintl\c()`. `assertRenders` / `assertRendersContaining` ride
  PHPUnit's `Assert`; `render()` alone needs none. The suite's hostile
  payloads prove escaping is under test too (child payloads escape, hostile
  URLs block, quote breakouts escape).
- **§17.1-Q3 advanced LSP surface** (`crates/lintl-lsp/src/workspace.rs`):
  `textDocument/rename` (component + prop renames as a `WorkspaceEdit` over
  the open documents — declaration and every tag/attribute usage, open and
  close), `textDocument/references` (component tag usages / prop attribute
  usages, declaration behind `includeDeclaration`), and `workspace/symbol`
  (case-insensitive subsequence fuzzy search over declared components as
  FUNCTION symbols). Targets must be declared in the open workspace; the
  workspace is the open documents (the §17.1-Q3 persistent index stays
  backlog).
- **The Year-3 real `lintl migrate`**: no longer a thin `build
  --target=rfc` alias — it rewrites `.lintl.php` sources IN PLACE with the
  RFC-parity `new \Markup\Element` lowering (line-preserved),
  `--dry-run` prints a unified diff and writes nothing, `--backup` keeps
  the original bytes as `<file>.bak`, and files that fail to compile or
  whose components no migrated source declares are refused untouched.
  Cross-file components resolve through the migrated set's declared names.
- **§10 server adapters** (`php/runtime/src/transports.php`): the
  `SwooleFlushTransport`, `ReactPHPFlushTransport`, `FrankenPHPFlushTransport`
  and `RoadRunnerFlushTransport` lanes on the existing `FlushTransport`
  seam — each only owns HOW a chunk reaches the wire, so streaming never
  bypasses the escapers. The RoadRunner lane is exercised end-to-end
  against a real `rr serve` application server (the php job's new
  `adapters` CI step installs rr and runs the suite with `LINTL_E2E_RR=1`;
  the FrankenPHP lane runs over a real `php -S` server; the Swoole and
  ReactPHP lanes run against structural fakes — the extensions ship no
  autoloadable surface).
- **The RFC convergence runtime** (`php/markup`, `markup/markup`):
  `\Markup\Element` / `\Markup\Fragment` / `\Markup\Html` + `render()` —
  the runtime side the `--target=rfc` lowering needed
  (`docs/rfc-alignment.md`). Escape-by-default at print time with the same
  attribute routing the string target's helpers enforce; the e2e compiles
  one fixture with BOTH targets and asserts `\Markup\render(...)` renders
  the string target's bytes (`\Lintl\c(...)`). The package is standalone:
  RFC output runs with zero Lintl dependency.
- **The Laravel Blade bridge** (`php/blade`, `lintl/blade`): the
  `@lintl('Badge', ['name' => $user])` directive — compiles to a bridge
  render call, loads `.lintl.php` components through the §6.10 dev
  loader (compile-if-stale; prod builds autoload), renders through `c()`.
- **The Symfony Twig bridge** (`php/twig`, `lintl/twig`): the
  `lintl_render('Badge', {name: user})` Twig function — same loader +
  escaper contract, marked safe for markup so Twig does not double-escape
  the runtime's output.
- **§10 streaming & suspense runtime** (`docs/stream-alignment.md`):
  `Lintl\stream($tree, ?callable $flush = null)` walks a stream-target
  render tree progressively (chunk order is the flush order); the
  `<Suspense>` boundary (`new \Lintl\Suspense(fallback: …, work: …)`)
  flushes its placeholder immediately, resolves the work in a fiber pumped
  round-robin, and flushes the resolved content **out of order** inside
  `<template id="lt-N-r">…</template><script>lintlSwap("lt-N")</script>`
  with a one-time 184-byte swap runtime replacing the placeholder in place.
  Resolved values render through `c()` — no streaming path bypasses the
  escapers (streaming threat cases in the §7.2 corpus) — the sync target
  runs boundaries inline, and the flush-order e2e lives in
  `php/runtime/tests/StreamingSuspenseTest.php`.
- **§10 flush transports** (`Lintl\FlushTransport` + `stream_via`): the
  CLI lane (`CliFlushTransport`) and the FPM lane (`FpmFlushTransport`,
  `X-Accel-Buffering: no` + buffered-output teardown), the FPM adapter
  exercised over a real `php -S` HTTP server in
  `php/runtime/tests/StreamingTransportTest.php`; the four server adapters
  (RoadRunner/Swoole/FrankenPHP/ReactPHP) landed on top of the same seam.
- The §10 suspense demo: `php scripts/suspense-demo.php` (capture) or
  served with `php -S` for the progressive HTTP view.
- **Type-driven escape elision** (§7.3-Y2, `docs/type-elision.md`): the
  `lintl analyze` path — `php/lintl-phpstan/bin/analyze` runs the PHPStan
  bridge's `LintlTypesCollector` over the prepared cache and writes
  `<source>.lintl-types.json`; `lintl analyze <paths> [--types PATH]
  [--target=…][--format=text|json]` compiles with the proven
  `int`/`float`/`numeric-string`/`literal` children folded past the v0.1
  ladder (never over it), reports the elision counters (children /
  considered / elided / rate) on stderr, and compiles byte-identical to
  `lintl build` when the report is absent. `bool` deliberately keeps the
  helper: `c()` renders bools as `''` while raw interpolation renders
  `'1'` — no fold preserves the output. The `analyze_children` bench
  drift-checks the counters.

- **The tree-sitter LSP lane** (§17.1 Q3's "tree-sitter grammar", the
  Phase 11 M1 card): `crates/lintl-lsp/src/tree_sitter.rs` runs the
  upstream `tree-sitter-php` grammar as an independent second parse of
  every indexed source, and `textDocument/definition`,
  `textDocument/rename` and `textDocument/references` consult the
  tree-sitter view IN ADDITION to the lintl-core scanner's (the Phase 9
  persistent index): the queries read a merged declaration table (the
  union, deduplicated by name + offset — the lanes' byte offsets agree),
  so a component only one lane sees still resolves, renames and lists
  references. A file whose tree-sitter parse cannot see its declarations
  (a broken declaration header such as `function Badge(***): Html`)
  falls back to the scanner alone, and the per-file lane
  (`tree-sitter` / `scanner-fallback`) rides `.lintl-cache/lsp-index.json`
  (shape version 2) across sessions. Markup regions stay the scanner's
  authority — the PHP grammar does not model JSX, and no upstream JSX
  extension exists to reuse (the card's documented grammar limit). The
  acceptance is a monorepo-fixture integration test
  (`crates/lintl-lsp/tests/tree_sitter.rs`): cross-file definition into
  a closed file, rename spanning declaration + invocation, references
  across the session cache, and the malformed file staying declared
  through the fallback.
- **The RoadRunner progressive per-boundary timing lane** (§10, the
  Phase 11 M2 card; closes the "progressive per-boundary timing on
  RoadRunner is CI-lane work" note): `bench/lib/ProgressiveTiming.php`
  renders a three-boundary `<Suspense>` page through the REAL
  `RoadRunnerFlushTransport` (a recording worker drains
  `respond()`, one frame per chunk), models deterministic per-boundary
  latency (`usleep` slices interleaved with `Fiber::suspend()`), and
  measures the time to the first placeholder flush (µs), the first
  resolved chunk and the fully resolved page — asserting INSIDE the
  harness that the placeholder for boundary N flushes before the
  resolved content for boundary N-1, resolution stays in order for the
  deterministic latencies, and the RR wire order equals the flush order.
  A broken flusher fails the lane instead of producing numbers. The lane
  is wired into `bench/run.php` (the S6 section + `progressive-timing.json`),
  CI's `bench` job through `make bench` (both the Docker-pinned and
  native lanes; `spiral/roadrunner-http` rides bench's dev deps for the
  `HttpWorkerInterface`), and a Rust integration test
  (`crates/lintl-cli/tests/progressive_timing.rs`) drives the CLI entry
  (`bench/lib/progressive_invariant.php`) under `PHP_BIN`.
- **The Windows daemon socket lane** (T-12's carried deferral, the
  Phase 11 M3 card): a `windows-daemon` CI job runs the whole watch suite
  on a `windows-latest` runner over the daemon's loopback-TCP fallback —
  serve + recompile-on-change, the build-cache-backed rebuilds, the
  concurrent-clients lane and the p50/p99-vs-spawn measurement (serial
  threads: each test tears down a scratch directory whose socket the
  next daemon must not hold open on Windows's strict directory locking).
  `docs/daemon-protocol.md` and the watch module docs record the closure.


- **Function-level context headers on the `migrate --dry-run` diff** (the
  Phase 9 §f cosmetic note): each hunk header carries the nearest
  enclosing function signature — `@@ -10,5 +10,5 @@ function Badge(string
  $name): Html` — so reviewing a migration shows which component is being
  rewritten. The convention is git's funcname header, PHP-shaped:
  visibility/static modifiers peel off first, a closure's `function (` and
  the arrow `fn` spellings name no context, and a long signature truncates
  at 80 chars with an ellipsis. Regression-tested by
  `crates/lintl-cli/tests/migrate.rs` on a two-component fixture whose
  separate hunks each carry their own function header.
- **The seeded fuzz corpus** (`fuzz/corpus/compile_fuzz/`, generated and
  verified by `crates/lintl-core/tests/fuzz_corpus.rs`): `cargo fuzz` no
  longer starts from an empty directory — the corpus seeds from the 220
  differential acceptance templates (deterministically replayed through
  the same proptest strategies the acceptance runs, so corpus and
  acceptance cannot drift), the 23 isolated reconciliation cases, the
  tree-sitter lane's fallback edge shapes (the `(***` broken header, the
  declaration error recovery swallows after a markup region) and the §7.2
  threat-corpus payload vectors as compiler inputs — 279 seeds over the
  known-good and known-bad boundaries. The fuzz target also drives a full
  LSP session per input (initialize → didOpen → shutdown → exit), so the
  scanner-fallback lane is fuzzed over arbitrary bytes, not just its
  unit-test probes; CI's ten-minute lane seeds the corpus before it runs.
- **The v1.0 readiness claims sweep** (`scripts/claims-sweep.sh`, `make
  claims`, wired into `make ci` and the CI docs job): greps the
  user-facing docs (README, the `docs/` contract pages, the docs-site
  pages) for stale pre-1.0 / v0.x / experimental claims and fails on any
  outside the explicit allowlist (the genuinely-open backlog notes, each
  named with its reason). README's tagline and Status section, §21.1's
  stale rows (T-09+ "not started", T-10's "daemon stays future work",
  T-21's "Q3 backlog" list), the rule-registry page coverage and the
  node-visitor scope note now state what actually shipped.

### Changed

- **The T-12 latency bound is statistically sound for slow runners** (the
  Phase 11 report's single Windows p99 flake): the nearest-rank p99 of 30
  samples is literally the max of the sample, so one scheduling hiccup on
  a 2-vCPU runner decided the verdict although the true lane gap is ~30×.
  The assertion is now daemon **p95** < spawn p50 over **60** samples
  (three tolerated outliers), with one bounded re-measurement of the
  whole round on failure — a real regression fails both rounds and the
  test fails loudly with both rounds' numbers. The p50/p95/p99 printouts
  stay for the record.

### Fixed

- **The background `lintl watch` spawn stopped its own daemon**: the
  readiness probe sent the `quit` request on its poll-connect, so the
  freshly spawned daemon shut down the moment `spawn_background` declared
  it ready (the Phase 2 background lane had no test coverage). The probe
  now opens the connection and closes it without sending — the daemon
  treats the empty read as a probe and serves on; the contract (and the
  quit frame's real shape) is pinned by `docs/daemon-protocol.md`.
- The build path bound a key it never used in the cache-hit arm
  (`crates/lintl-cli/src/lib.rs`), which the current stable toolchain
  flags under the `-D warnings` gate the Phase 9 pass landed on an older
  one — the lookup no longer carries the key through the hit.

- **The stream target's declared return type TypeErrored against its own
  artifact** (the Phase 9 `renderStreaming()` acceptance proved it — the
  first real PHP consumer of a stream-target artifact): the §10 lowering
  wrapped the body in a generator closure but kept the author's
  `: Html` return type, so invoking the component under `strict_types`
  failed with `Return value must be of type Html, Generator returned`.
  The scanner now rewrites a declared `Html` return (canonical, nullable
  and qualified spellings) to the non-null `\Generator` on the same line
  when the stream lowering is active; unions and body-less declarations
  copy verbatim. Regression-tested in `tests/stream_target.rs`.
- **The bare `--manifest` write depended on the process cwd** (the Phase 8
  backlog's stray empty `lintl.json` at the repo root): the default
  `lintl.json` now anchors to the workspace being compiled — the common
  ancestor of the build inputs and `--out` — never the process cwd, so a
  lane invoking the engine from anywhere else cannot scatter the manifest
  outside the workspace. The blade/twig console suites no longer chdir
  for the write, and both assert no stray manifest lands at the runner's
  cwd.

- The Phase 7 bool-elision PHPStan fixture's report-resolution assertion
  (`php/lintl-phpstan/tests/AnalyzeElisionTest.php`): the fixture typed the
  hostile prop `string`, which wins the §7.3 elision ladder before the
  analyze report is consulted, so the mis-proof case could never fire and
  the suite stayed red. The fixture's prop is untyped now — the report's
  `bool` claim is the only proof, the fold renders the constant `''`, and
  the PHPStan suite is green (13 tests) with no skips.



- The pedantic-clippy gate regression in the newest CLI code (four
  warnings): `lintl-cli`'s unused `types_flag` helper is used again by the
  `--types` parse arms (the inline duplicates are gone), its mangled doc
  comment is restored to `parse_args`, the duplicated `--to` handling is
  the shared `migrate_to` helper (`parse_args` back under the
  `too_many_lines` budget), and `tests/stale_hints.rs` uses the
  message-carrying `assert!(…is_empty(), …)` and drops a needless borrow.
  The gate (`clippy --workspace --all-targets --all-features -- -D
  warnings -W clippy::pedantic`) is zero-warning again, no `#[allow]`
  anywhere.
- The `analyze_children` bench drift-check was red on `main` (never able
  to fire): the hint scanner grepped for `page {{$page}} of` — the
  double-brace spelling as written in Rust source — while the source
  builder's `writeln!` format escaping emits the literal `page {$page} of`
  (single braces), so the scan found zero hints and the bench died on
  `assert_eq!(hints.len(), 20)` before measuring. The scanner now matches
  the emitted bytes and the drift-check runs (40 dynamic children / 20
  elided / rate 0.5).
- Root PHPStan level max is clean again: the bridge's `json_decode` shapes
  decode through `Bridge::decodeDiagnostic` into validated field shapes
  (no ignores, no level changes), the Plugin's `prod.artifacts` lookup
  validates the `prod` object first, and the Composer autoloader map reads
  its documented shape directly.
- `scripts/php-gates.sh` `php -l` no longer sweeps the `.lintl.php` JSX
  fixtures (compiler input, not PHP — the exclusion phpstan.neon already
  documents), and its subcommand mode propagates failures instead of
  exiting 0 on red (a CI blind spot).

### Initial MVP scope (2026-11-20)

The 14-day plan's MVP (architecture doc §15) — compiler core, CLI, PHP
runtime, dev loader, playground, benchmark harness and docs site v0. The
above `### Added` section extends this MVP to the full shipped feature
set; this subsection preserves the original MVP bullets for the
historical record.

#### Compiler — `lintl-core`

- PHP-aware scanner: strings, heredocs/nowdocs, comments, `#[attributes]`,
  inline HTML and `?>` pass through **byte-identically** when a file holds
  no JSX (T-03 golden suite).
- JSX parser + string-target emit with JSX whitespace rules (T-04), raw-text
  `<script>`/`<style>` bodies (§4.7.1) and line-preserving output — every
  non-JSX token keeps its source line (T-06 invariant test).
- `--target=stream` lowers components to generator closures whose `use`
  lists carry every referenced local, transitively through nested children
  closures (F1, §21.2).
- `--target=rfc` emits `\Markup\*` lowering for RFC parity experiments.
- Attribute helpers: static folding (§4.4), URL allowlist (`u()`), srcset
  candidate validation, `cls()`/`sty()` maps, spread routing with `on*` and
  unsafe-name rejection (§7.1/§7.2 threat corpus).
- Escape elision for typed `string` parameters, `(int)`/`(float)` casts and
  `count()` (§7.3 v0.1).
- Diagnostics with miette rendering, JSON output (`lintl build --format
  json`), source maps (`--map`), visitor and rule-registry seams,
  cross-file signatures, component inventory and suppression directives.

#### CLI — `lintl-cli`

- `lintl init` scaffolds a runnable demo; `lintl build` (with the
  SHA-256 content-addressed cache, `--in-place`/`--out`), `lintl check`,
  `lintl watch`, `lintl stats` and the `init --demo N` gallery (T-10,
  T-15).

#### PHP packages

- `lintl/runtime` — the only production dependency: `Html`, `c()/a()/u()/
  srcset()/cls()/sty()/attrs()` (§6.8), threat-corpus PHPUnit suite, PHPStan
