# LNL0104 — invalid spread expression

`error[LNL0104]` · parse diagnostic (never suppressible) · scanner (§6.3)

## What fires it

A spread attribute is not written as `{...expr}`:

```php
<?php
return <div {...$attrs}>text</div>;
```

A spread must be the literal three-dot form `{...expr}` inside an
attribute position. The scanner rejects `{...}` with no expression,
`{..$attrs}` (two dots), or `$attrs` alone — the lowering emits a PHP
named-argument spread (`...$attrs`) only from the JSX three-dot form, so
any other shape would emit invalid PHP.

## Fix

Write the spread as `{...$attrs}` (or `{...['href' => $url, 'class' => 'btn']}` for an inline map). Each key in the spread routes through the
attribute rules — an `onclick` key is still LNL0301, a `<`-in-name is
still rejected by the spread guard (§7.2).
