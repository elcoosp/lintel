# LNL0301 — dynamic event-handler attribute

`error[LNL0301]` · validation diagnostic (error severity — fails `compile()`) · `DynamicHandlerRule` (§7.1 "no JS-in-attribute from data")

## What fires it

A component or element attribute named `on*` whose value is an
expression:

```php
<?php
return <button onclick={$handler}>Go</button>;
```

```text
error[LNL0301]: dynamic event-handler attribute `onclick` is not allowed
  = help: use `data-action={...}` (or an `hx-*` / `x-on:*` binding) and attach
          behaviour in JavaScript
```

## Why it is an error

An `on*` attribute value is executed as JavaScript by the browser. If the
value is dynamic, untrusted data becomes executable script — the
highest-impact XSS sink an HTML templating language can offer (§7.1
escaping matrix). Lintl refuses the sink outright instead of escaping
it: escaping cannot help, because the value is *supposed* to be code.

## Fix

Bind behaviour outside the markup: put a stable name in the attribute
(`data-action={...}`) and attach the listener in JavaScript, or use an
HTMX/Alpine binding (`hx-*`, `x-on:*`), which are static-name attributes
and escape their *values* normally. A static *string* handler
(`onclick="track('x')"`) is allowed but discouraged — see LNL0302, which
rides along as a warning. Pinned by
`crates/lintl-core/tests/validation.rs` and enforced again at runtime by
`Lintl\attrs()` (§6.8), which throws on any `on*` spread key.
