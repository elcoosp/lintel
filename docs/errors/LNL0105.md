# LNL0105 — unexpected input

`error[LNL0105]` · parse diagnostic (never suppressible) · scanner (§6.3)

## What fires it

The scanner expected a specific character at the current position and
found something else:

```php
<?php
return <div class="btn">text</span>;
```

```text
error[LNL0105]: expected `</div>`, found `</span>`
```

This is the generic "the grammar cannot recover here" diagnostic: a
close tag that does not match the open stack is LNL0102 (mismatched
close); an element that never closes is LNL0101 (unterminated). LNL0105
covers the remaining cases — a missing `=`, a stray `}`, a JSX expression
that ended where the scanner expected a name. The `help:` line names the
expected character when the grammar knows it.

## Fix

Read the `help:` line: it names what the scanner expected. The fix is
usually to add the missing token (`=`, `}`, `/>`) or to correct the
preceding element. Parse errors are never suppressible — the emitted PHP
would be invalid.
