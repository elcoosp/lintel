# LNT0202 — component attribute cannot become a PHP named argument

`error[LNT0202]` · validation diagnostic (error severity — fails `compile()`) · `HyphenArgRule` (§6.7)

## What fires it

A component attribute whose name is not a PHP identifier — typically
hyphenated (`data-x`, `aria-label`):

```php
<?php
return <Card data-id="7" />;
```

```text
error[LNT0202]: component attribute `data-id` cannot become a PHP named argument
  = help: pass it through a spread instead: `<Card {...['data-id' => value]} />`
```

## Why it is an error

Component attributes compile to PHP named arguments
(`Card(data_id: …)` would be the only possible lowering, and PHP named
arguments cannot contain hyphens — the call would be a parse error at
runtime). HTML attributes are case-insensitive and dash-friendly; PHP
identifiers are not. The rule runs on component invocations only:
`<div data-id="7">` is ordinary HTML and compiles verbatim.

## Fix

Use a spread so the map key keeps the exact spelling the runtime needs:
`<Card {...['data-id' => '7']} />` compiles to `\Lintel\attrs([...])`,
which validates and routes each key. Or design the component to accept
the prop as a PHP identifier (`dataId`) and translate inside the
component. Spreads bypass named-argument rules by contract. Pinned by
`crates/lintel-core/tests/validation.rs`.
