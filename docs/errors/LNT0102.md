# LNT0102 — mismatched closing tag

`error[LNT0102]` · parse diagnostic (never suppressible) · scanner (§6.3)

## What fires it

A closing tag does not match the innermost open tag:

```php
<?php
return <div>
    <span>text</div>
</div>;
```

The scanner keeps a stack of open elements. When it reads `</name>`, the
name must equal the element on top of the stack; anything else is a
structure error, because the emitted PHP would otherwise close a string
concatenation for an element that is still open.

## The "did you mean" help line

A near-miss spelling of the open tag — same first character, within a
small edit distance — carries a `help:` suggestion instead of a bare
error:

```text
error[LNT0102]: expected </span>, found </spam>
  = help: did you mean `</span>`? (1 edit(s) away)
```

An unrelated close tag gets no suggestion: the help line must never guess
when the author may genuinely have wanted a different structure. The
contract is pinned by `crates/lintel-core/tests/parse_errors.rs`.

## Fix

Close the element you opened, in the order you opened it — JSX elements
must nest like PHP blocks. Fragment closes (`</>`) match a fragment open,
not an element.
