# LNT0401 — void element with children

`error[LNT0401]` · validation diagnostic (error severity — fails `compile()`) · `VoidChildrenRule` (§4.2 content model)

## What fires it

A void element — one that HTML grammar defines as having no content
(`<br>`, `<img>`, `<input>`, `<hr>`, `<meta>`, `<link>`, `<source>`,
`<area>`, `<base>`, `<col>`, `<embed>`, `<track>`, `<wbr>`) — is given
children:

```php
<?php
return <br>unexpected</br>;
```

```text
error[LNT0401]: void element `<br>` cannot have children
  = help: remove the children or switch to a non-void element
```

## Why it is an error

The HTML parser drops an author's attempt to put content inside a void
element — `<br>text</br>` renders the text *outside* the element, so the
markup the author wrote is not the page the browser shows. Lintel
lowering would concatenate the children into the tag's string anyway,
widening the gap between source and rendered output; refusing at compile
time keeps the tree honest. Self-closing JSX syntax (`<img src={$src} />`)
is unaffected — it has no children by definition.

## Fix

Remove the children, or switch to a non-void element (`<span>`, `<div>`,
`<p>`) when content was actually intended. Pinned by
`crates/lintel-core/tests/validation.rs`.
