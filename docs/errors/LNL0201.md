# LNL0201 — component shadows a PHP builtin function

`error[LNL0201]` · validation diagnostic (error severity — fails `compile()`) · `BuiltinShadowRule` (§6.7, doc §17 "style collisions")

## What fires it

A component invocation whose name lowercases to a PHP builtin function
that the file neither declares nor imports:

```php
<?php
return <Header title="hi" />;   // PHP builtin header() — error
```

```text
error[LNL0201]: component `Header` shadows the PHP builtin function `header()`
  = help: declare `function Header()` in this file or add `use function header;`
          so the call resolves to your component
```

## Why it is an error

Components compile to plain PHP named-argument calls (`Header(title: …)`).
PHP function calls are case-insensitive, so `<Header>` would resolve to
the builtin `header()` at runtime — silently sending a header instead of
rendering. The rule only fires when the call would actually escape to the
builtin: a file that declares `function Header(...)` (or
`use function ...;`) keeps the author's meaning, and the scanner's
declared-function table proves it before the diagnostic fires.

## Fix

Either name the component something that does not collide (`<PageHeader
/>`), or declare/import the function so the call resolves to your
component. Namespaced components (`<Ui\Header />`) never collide. Pinned
by `crates/lintl-core/tests/validation.rs`.
